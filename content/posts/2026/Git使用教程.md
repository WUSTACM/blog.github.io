# Git 基础使用指南

Git 是一种分布式版本控制工具，可以记录文件的修改历史，帮助我们管理代码版本，并与他人协作开发。本文介绍 Git 本地仓库、提交记录、分支、标签和远程仓库的常用操作。

## 一、创建并管理本地仓库

### 1. 初始化仓库

新建一个空文件夹，在文件夹内单击鼠标右键，选择 **Open Git Bash Here**，然后执行：

```bash
git init
```

执行后，Git 会在当前目录中创建一个隐藏的 `.git` 文件夹，用于保存仓库的版本信息。

> `.git` 文件夹是 Git 仓库的核心数据目录，不要随意删除或修改其中的内容。

### 2. 查看仓库状态

完成文件的增加、删除或修改后，可以使用以下命令查看工作区状态：

```bash
git status
```

该命令会显示哪些文件发生了变化，以及哪些变化已经被添加到暂存区。

### 3. 将修改添加到暂存区

将指定文件添加到暂存区：

```bash
git add test.txt
```

其中，`test.txt` 是文件名。

如果希望一次添加当前目录中的所有修改，可以执行：

```bash
git add .
```

### 4. 取消暂存

如果误将文件添加到了暂存区，可以执行：

```bash
git restore --staged test.txt
```

该命令只会将 `test.txt` 移出暂存区，不会删除工作区中的文件，也不会撤销文件内容的修改。

### 5. 提交修改

将暂存区中的内容提交到本地仓库：

```bash
git commit -m "新增文件"
```

参数 `-m` 表示为本次提交添加说明。提交信息应尽量简洁、明确地描述本次修改。

## 二、查看提交记录

### 1. 查看完整日志

```bash
git log
```

该命令会显示提交版本号、作者、日期和提交信息等内容。

### 2. 简洁显示日志

```bash
git log --oneline
```

添加 `--oneline` 后，每次提交只占一行，便于快速浏览。

### 3. 查看某次提交及其之前的记录

```bash
git log --oneline <提交版本号>
```

将 `<提交版本号>` 替换为实际的提交哈希值，例如：

```bash
git log --oneline 79378a4
```

## 三、撤销修改与恢复文件

在执行撤销操作前，建议先运行 `git status` 和 `git log --oneline`，确认文件当前所处的状态。

### 1. 恢复尚未提交的修改

如果文件的修改或删除操作还没有提交，并且希望将其恢复为暂存区或最近一次提交中的状态，可以执行：

```bash
git restore test.txt
```

> 该操作会覆盖工作区中尚未提交的修改，执行前应确认这些修改已经不再需要。

### 2. 撤销已经提交的操作

先查看提交记录，找到需要撤销的提交：

```bash
git log --oneline
```

然后执行：

```bash
git revert e6cd120
```

其中，`e6cd120` 是需要撤销的提交版本号。`git revert` 会创建一个新的提交，用相反的修改抵消目标提交，因此不会破坏原有提交历史，适合已经推送到远程仓库的提交。

### 3. 将仓库回退到指定版本

```bash
git reset --hard 79378a4
```

其中，`79378a4` 是目标版本号。该命令会将当前分支、暂存区和工作区全部回退到指定版本，并丢弃之后尚未保存的修改。

> `git reset --hard` 具有破坏性。对于已经推送到远程仓库的提交，通常优先使用 `git revert`。

## 四、分支操作

分支可以让开发者在不影响主线代码的情况下开发新功能或修复问题。

### 1. 查看分支

```bash
git branch
```

命令输出中带有 `*` 的分支是当前所在分支。

### 2. 创建分支

```bash
git branch user
```

该命令会创建名为 `user` 的分支。仓库通常需要至少存在一次提交，才能基于当前提交创建分支。

### 3. 切换分支

```bash
git switch user
```

也可以使用传统写法：

```bash
git checkout user
```

### 4. 创建并切换到新分支

```bash
git switch -c order
```

也可以使用：

```bash
git checkout -b order
```

上述命令都会创建名为 `order` 的分支，并立即切换到该分支。

### 5. 合并分支

假设需要将 `order` 分支的修改合并到 `main` 分支：

```bash
git switch main
git merge order
```

`git merge order` 的含义是：将 `order` 分支合并到当前所在分支。因此，合并前应先切换到接收修改的目标分支。

### 6. 解决合并冲突

当两个分支修改了同一文件中的相同位置，且 Git 无法自动判断应保留哪一部分时，可能产生合并冲突。

此时可以按照以下步骤处理：

1. 执行 `git status`，查看发生冲突的文件。
2. 打开冲突文件，根据冲突标记选择或整合需要保留的内容。
3. 删除文件中的冲突标记并保存。
4. 将解决后的文件重新加入暂存区并提交：

```bash
git add <冲突文件名>
git commit
```

### 7. 删除分支

```bash
git branch -d user
```

该命令会删除已经完成合并的 `user` 分支，但不能删除当前所在的分支。

## 五、标签操作

标签通常用于给某个重要提交添加易于识别的名称，例如软件版本 `v1.0.0`。

### 1. 创建标签

为当前提交创建标签：

```bash
git tag v1.0.0
```

为指定提交创建标签：

```bash
git tag v1.0.0 <提交版本号>
```

标签名称不能重复。

### 2. 查看标签

```bash
git tag
```

### 3. 删除标签

```bash
git tag -d v1.0.0
```

### 4. 基于标签创建分支

```bash
git switch -c addfile v1.0.0
```

该命令会以标签 `v1.0.0` 指向的提交为起点，创建并切换到 `addfile` 分支。标签本身不是分支，不能随着新提交向前移动。

## 六、使用 Git 管理远程仓库

### 1. 克隆远程仓库

在目标文件夹内打开 Git Bash，执行：

```bash
git clone <仓库地址>
```

在 GitHub 仓库页面中，依次点击 **Code → Local → HTTPS**，即可复制仓库地址。

如果希望为克隆到本地的文件夹指定名称，可以执行：

```bash
git clone <仓库地址> <本地文件夹名>
```

例如：

```bash
git clone https://github.com/user/example.git my-project
```

### 2. 查看远程仓库

```bash
git remote -v
```

通常，克隆仓库时 Git 会自动将远程仓库命名为 `origin`。

### 3. 拉取远程更新

```bash
git pull origin main
```

该命令会获取远程 `main` 分支的最新提交，并合并到当前分支。多人协作时，建议在推送前先同步远程更新。

### 4. 推送本地提交

首次推送当前分支时，可以执行：

```bash
git push -u origin main
```

其中，`origin` 是远程仓库名称，`main` 是需要推送的本地分支。参数 `-u` 会建立本地分支与远程分支的跟踪关系。

建立跟踪关系后，后续通常可以直接执行：

```bash
git push
```

## 七、常用工作流程

日常使用 Git 时，可以按照以下顺序操作：

```bash
git status
git add .
git commit -m "描述本次修改"
git pull --rebase
git push
```

其中，`git pull --rebase` 会先同步远程提交，再将本地提交接到最新远程提交之后，使提交记录更加整洁。如果执行过程中产生冲突，需要先解决冲突，再继续变基操作。

Git 的核心流程可以概括为：在工作区修改文件，将修改添加到暂存区，再提交到本地仓库，最后推送到远程仓库。熟悉这条主线后，再逐步掌握分支、标签和撤销操作，会更加容易理解 Git 的整体工作方式。
